Q&M AI Enquiry & Enrollment System

How a free-text message finds its agent

One WhatsApp thread, three specialist agents, and a router that tries hard not to ask the LLM anything it can already infer for free.

backend/app/orchestrator.py backend/app/crews/router.py CrewAI · GPT-4o-mini

Architecture overview

A message crosses five stages before a reply goes out: ingress, registration, a three-tier routing decision, a specialist agent's own reasoning loop, and a write-back that lets the next message skip the expensive parts entirely.

Query processing pipeline, step by step

The same eight steps run for every free-text message, from "hi" to a mid-enrollment "yes go ahead". What changes between them is which lane resolves the routing, and which module + tools pick it up.

01

Message arrives at the gateway

The Node gateway (whatsapp-web.js) receives the WhatsApp message and forwards it as JSON to the Python backend — no processing happens on the gateway side.

main.py:77 — POST /webhook/whatsapp
02

Orchestrator resolves the customer

handle_inbound() upserts the sender into customers by their stable WhatsApp id, then checks the registration gate — but only if routing is about to land on Module B. Module A and C never block on it.

orchestrator.py:815-871, 1013-1041
03
Lane ① · media

Image attached? Skip straight to Module C

A payment screenshot never touches the classifier. The router checks for media before anything else and forces Module C — vision verification and payment recording are deliberately kept outside LLM judgement.

router.py:683-689
04
Lane ② · Tier 0

Is a question already pending?

conversation_state is checked for an owning module left over from the last turn. If nothing in the new message clearly names a different module, it's dispatched straight back — this is how "14 Aug" or "yes" resolve correctly without ever reaching an LLM.

router.py:585-652
05
Lane ③ · Tier 1

Classify the free text

Only on a Tier 0 miss: an LLM call labels the message ENQUIRY, ENROLLMENT, or PAYMENT (a keyword heuristic substitutes if OPENAI_API_KEY is unset). Low confidence returns a disambiguation menu instead of guessing.

router.py:367-582
06

The specialist agent reasons and acts

The chosen module builds a CrewAI agent with its own persona and tool set, hands it the last few turns of chat history plus the new message, and lets it call tools — each one a thin wrapper over services/ business logic, the same functions any deterministic path would call.

module_a.py:821-1096 · crews/_base.py:107-184
07

State is written back before the reply goes out

The module returns a result that says whether a question is still open. If so, conversation_state is updated with the owning module and the resolved slots (course, intake, candidates); if not, it's cleared. This is what Tier 0 reads on the next turn.

orchestrator.py:760-793
08

Reply delivered

The text is posted back to the gateway's /send-reply, which resolves the original chat id and sends it — closing the loop on the same WhatsApp thread the message arrived on.

whatsapp_client.py:17-35

Specialist agents & their tools

Tools are thin — each one delegates to services/ and is shared across modules where it saves an agent a round trip (Module B borrows Module A's course lookups; Module C borrows Module B's enrollment lookups).
